## TECHNICAL SPECIFICATION: I2C BUS PROTOCOL
The Inter-Integrated Circuit (I2C) protocol is a synchronous, multi-master, multi-slave, packet-switched, single-ended, serial communication bus. It is optimized for short-distance, intra-board communication between microcontrollers and low-speed peripheral ICs.
## 1. Physical Layer & Wiring
I2C minimizes pin counts by utilizing an open-drain/open-collector architecture.
## 1.1 Bus Architecture
The bus requires only two lines plus a common ground reference:

* SDA (Serial Data Line): Bi-directional line for data transmission.
* SCL (Serial Clock Line): Synchronizing clock signal generated by the master.
```text
       VCC (3.3V / 5V)

        |          |
       [R]        [R]  <-- Pull-up Resistors (e.g., 4.7 kΩ)

        |          |
  +-----+----------+-----------------------+ SDA

  |     |          |                       |
  |  +--+----------+--------------------+  | SCL
  |  |  |          |                    |  |
+-------+--+    +--+-------+         +--+--+----+
|          |    |          |         |          |
|  MASTER  |    | SLAVE 1  |         | SLAVE 2  |
|          |    |          |         |          |
+----------+    +----------+         +----------+
```
## 1.2 Pull-Up Resistors
Because I2C devices can only actively pull lines LOW, pull-up resistors are mandatory to pull the lines HIGH when the bus is idle.

* Standard Mode (100 kHz): ~4.7 kΩ
* Fast Mode (400 kHz): ~1.0 kΩ to 2.2 kΩ (lower resistance overcomes bus capacitance faster)
* Physical Constraint: Total bus capacitance must not exceed 400 pF, limiting distance to roughly 2 meters.


## 2. Bus States & Bit Signaled Conditions
Data on the SDA line must change only while SCL is LOW. If SDA changes while SCL is HIGH, it is interpreted as a bus control condition (START, REPEATED START, or STOP).
```text
SCL  ____/¯¯¯¯\____      ____/¯¯¯¯\____      ____/¯¯¯¯\____
         Valid               START               STOP
SDA  XXXXXXXXXXXXXX      ¯¯¯¯\_________      ________/¯¯¯¯¯
```

* START (S): SDA transitions HIGH to LOW while SCL is HIGH. Initiates a transaction.
* REPEATED START (Sr): A START condition generated without a prior STOP. Keeps the bus claimed.
* STOP (P): SDA transitions LOW to HIGH while SCL is HIGH. Terminates the transaction.

## 3. Standard Register Read Transaction Sequence
Reading a specific register from a slave requires a two-phase sequence: a Write Phase to set the internal register pointer, followed by a Read Phase to fetch the data.
## 3.1 Step-by-Step Execution Protocol

   1. START Condition: Master pulls SDA LOW while SCL is HIGH to claim the bus.
   2. Slave Address (Write): Master sends 7-bit Slave Address + 1-bit Write (0).
   3. ACK: Target Slave pulls SDA LOW on the 9th SCL pulse.
   4. Register Pointer: Master sends the 8-bit Target Register Address.
   5. ACK: Slave pulls SDA LOW.
   6. REPEATED START: Master transitions SDA HIGH-to-LOW while SCL is HIGH without issuing a STOP.
   7. Slave Address (Read): Master sends 7-bit Slave Address + 1-bit Read (1).
   8. ACK: Slave pulls SDA LOW.
   9. Data Byte: Slave controls SDA and transmits the 8-bit register payload.
   10. NACK: Master leaves SDA HIGH on the 9th pulse to signal the end of reading.
   11. STOP Condition: Master releases SDA LOW-to-HIGH while SCL is HIGH to free the bus.

## 5. Advanced Bus Mechanisms & Troubleshooting

* Clock Stretching: A slave device can hold SCL LOW to pause transaction processing if its internal buffer is busy. The master must wait until SCL is released HIGH before continuing.
* Multi-Master Arbitration: If two masters transmit simultaneously, they monitor SDA. If a master detects SDA is LOW when it expected HIGH, it loses arbitration, silently drops off the bus, and lets the other master finish cleanly.
* Bus Hang Handling: If a slave is interrupted mid-byte, it may hold SDA LOW indefinitely, freezing the bus. The master can recover by generating 9 clock pulses on SCL to force the slave to complete its state machine and release SDA.

## 5.1 Multi-Master Arbitration Mechanics & Priority
I2C supports true multi-master environments using a non-destructive bitwise arbitration process.
## 5.1.1 Priority Bias toward Lower Addresses
The bus priority is mathematically biased toward the lowest slave address value. For example, a master attempting to communicate with Slave Address 0x0C (0001100b) will always win arbitration over a master attempting to communicate with Slave Address 0x4C (1001100b).
## 5.1.2 The Open-Drain Consequence
This prioritization is a direct physical consequence of the open-drain bus architecture.

* On an open-drain line, a dominant state is LOW (driven by a transistor to ground), while a recessive state is HIGH (floating, pulled up by a resistor).
* If one master attempts to transmit a passive 1 (HIGH) while another master transmits an active 0 (LOW), the master transmitting the 0 will actively pull the line down, forcing the physical bus voltage to LOW.

## 5.1.3 Step-by-Step Arbitration Example
When two masters generate a START condition simultaneously, they both transmit their target slave addresses bit-by-bit onto the SDA line while monitoring the real-time voltage state of the bus.
```text
Master A (Addr: 0x4C) ->  0  1  0  0  1  1  0  0  
Master B (Addr: 0x0C) ->  0  0  0  1  1  0  0  0

                          |  |
Bus State Result --------> 0  0  <-- Master A detects SDA is LOW while trying 

                          |  |      to send HIGH. Master A drops out here!
                          ^  ^
                        Bit7 Bit6

```
1. Bit 7: Both Master A and Master B drive 0 (LOW). The bus is LOW. Both see a match and continue.
2. Bit 6: Master A releases the line to send a 1 (HIGH). Simultaneously, Master B drives the line to a 0 (LOW) because its target address requires it.
3. The Collision: Because of the open-drain interaction, Master B's transistor pulls the physical SDA line LOW.
4. Arbitration Loss: Master A samples the SDA line during this clock cycle and expects to see a HIGH state. Instead, it reads a LOW state.
5. Bus Release: Recognizing it has lost arbitration to a device that transitioned to LOW first, Master A immediately shuts down its SDA/SCL output drivers. Master B continues its frame uninterrupted without any data corruption or bus collision spikes.


## 6. Bus Protocol Comparison: I2C vs. SPI

| Feature | I2C Protocol | SPI Protocol |
|---|---|---|
| Physical Pin Count | 2 Pins (SDA, SCL) | 4+ Pins (MOSI, MISO, SCK, SS) |
| Duplex Capability | Half-duplex | Full-duplex |
| Device Selection | Software Address (7 or 10-bit) | Hardware Slave Select (SS) lines |
| Error Verification | Built-in ACK / NACK bit | None (requires software CRC layer) |
| Max Throughput | Lower (typically ≤ 1–5 Mbps) | Higher (frequently ≥ 10–50 Mbps) |
