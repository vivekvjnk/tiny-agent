# BL33: Non-Secure Bootloader Architecture (U-Boot / Barebox)

In the ARM Trusted Firmware (TF-A) boot architecture, **BL33** represents the final pre-kernel execution phase running in **Non-Secure EL2** (Hypervisor) or **Non-Secure EL1**. Its primary mandate is to initialize rich peripheral interfaces, parse boot scripts or image structures, load the OS kernel and Device Tree into DRAM, and transfer control to the Linux kernel.

---

## 1. System Position & Execution Context

```
+---------------------------------------------------------------------------------+
| SECURE WORLD (EL3)                                                              |
|   TF-A BL31 Runtime Monitor                                                     |
+---------------------------------------------------------------------------------+
                                         │
                                         │ ERET (Execution Return)
                                         v
+---------------------------------------------------------------------------------+
| NON-SECURE WORLD (EL2 / EL1)                                                    |
|                                                                                 |
|   +-------------------------------------------------------------------------+   |
|   | BL33 Execution Context (U-Boot Proper / Barebox)                        |   |
|   |   • Execution Memory: Main DRAM                                         |   |
|   |   • Exception Level: Non-Secure EL2 (or EL1 if virtualization disabled) |   |
|   |   • Privileges: Direct access to PCIe, eMMC, USB, Network, Graphics     |   |
|   +-------------------------------------------------------------------------+   |
|                                        │                                        |
|                                        │ Jumps to Kernel Entry (Image)          |
|                                        v                                        |
|   +-------------------------------------------------------------------------+   |
|   | Linux Kernel Execution                                                  |   |
|   |   • x0 = Physical Address of DTB (.dtb)                                 |   |
|   |   • MMU/D-Cache = Disabled | Interrupts = Masked                         |   |
|   +-------------------------------------------------------------------------+   |
+---------------------------------------------------------------------------------+
```

## 2. BL33 Core Subsystems & Responsibilities

| Subsystem | Mandates & Operations | Key Commands / APIs |
| --- | --- | --- |
| **Memory Allocation** | Maps full physical DRAM region, configures stack pointers, and establishes `gd` (Global Data) structure. | `bdinfo`, `meminfo` |
| **Storage & File Systems** | Reads kernel images and device trees from eMMC, SD, NVMe, SPI Flash, or SATA formatted with EXT4, FAT, or UBIFS. | `ls`, `load`, `ext4load`, `fatload` |
| **Network & NFS Boot** | Configures Ethernet PHY, DHCP IP address assignment, and fetches kernel/DTB via TFTP or NFS. | `dhcp`, `tftpboot`, `netboot` |
| **USB Gadget Mode** | Exposes board as USB Mass Storage device or Fastboot endpoint for flashing firmware binaries over USB. | `fastboot`, `ums 0 mmc 0` |
| **Environment Storage** | Stores non-volatile configuration variables in persistent boot storage (NVRAM, SPI NOR flash, eMMC boot partition). | `printenv`, `setenv`, `saveenv` |

## 3. Kernel Image Formats & Boot Commands Comparison

| Image Format | Header Structure | Compression Support | Boot Command | Typical Architecture Target |
| --- | --- | --- | --- | --- |
| **`Image`** | Raw uncompressed binary with 64-byte AArch64 arm64 header. | None (Uncompressed) | `booti <kernel> - <dtb>` | AArch64 (ARM64 Linux default) |
| **`zImage`** | Self-decompressing compressed kernel wrapper. | gzip / LZO / LZ4 | `bootz <kernel> - <dtb>` | ARM32 (32-bit Cortex-A) |
| **`uImage`** | Legacy U-Boot wrapper (64-byte header + checksum). | gzip / bzip2 | `bootm <kernel> <ramdisk> <dtb>` | Legacy ARM32 / MIPS / PowerPC |
| **`fitImage`** | Flattened Image Tree (ITS syntax, DTB structure encapsulating Kernel, Initrd, DTBs, signatures). | Multiple (gzip, xz, zstd) | `bootm <fit_addr>#config` | Modern Secure ARM64 / Embedded Linux |

## 4. Kernel Handoff Execution Pipeline

Before branching to the kernel entry point, BL33 executes a strict cleanup sequence:

```
 [Prepare Boot Parameters]  --->  Loads Image at text_offset (e.g. 0x80000) & DTB at DRAM address
                                          │
                                          ▼
 [Disable Peripherals]      --->  Stops active DMA engines, disables Ethernet controllers & USB
                                          │
                                          ▼
 [Cache Flush & Invalidate] --->  Flushes D-Cache lines to RAM, invalidates I-Cache (`ic iallu`)
                                          │
                                          ▼
 [Mask Interrupts]          --->  Disables CPU IRQ/FIQ signals in CPSR / PSTATE
                                          │
                                          ▼
 [Register Setup & Jump]    --->  x0 = DTB Address, x1-x3 = 0, MMU = OFF -> Jump to kernel entry
```
